### Deferred out of plan 004: `#include` re-inclusion semantics

Split out on 2026-08-04 after an implementation attempt showed the fix is worse
than the bug without an expansion budget. Both regressions were reproduced:

- **Cycle detection is keyed on the raw include token, not the resolved path**
  (`src/preprocessor.zig:232` checks `included_files.contains(path)`, and `:252`
  stores the unresolved spelling). Effects: every include is implicitly
  include-once regardless of `#pragma once`, so a header legitimately included
  twice is silently dropped the second time; and two different files sharing a
  relative spelling under different `-I` roots collide.
- **Why the obvious fix is not safe yet.** Re-keying on the resolved path makes
  `#pragma once` stop short-circuiting before I/O (resolve reads, `dupeZ`s and
  appends to `included_sources` before the pragma check, and the early return
  never pops it, so a guarded header is retained once per textual occurrence).
  Restoring correct double-inclusion also makes expansion exponential in depth:
  a 7-file probe produced 127 reads, and with `max_include_depth` at 16
  (`src/preprocessor.zig:35`) the worst case is 65535 reads and retained copies
  at up to 10 MiB each. The accidental include-once was bounding this.
- **Shape of a real fix**: check `pragma_once_files` on the resolved key BEFORE
  reading, pop `included_sources` on every early return, use an active-include
  stack (push/pop with `defer`) for genuine cycles, and add a total expansion
  budget modelled on the macro-expansion budget already in this file. Effort M,
  risk MED. Not a security issue: plan 004's containment work closes the
  traversal hole independently.

Also surfaced during that work and worth folding in: `unsafe_include_path` is
recorded by `recordUnsafeInclude` but read by nothing outside the tests, so a
refusal reaches the user as a generic preprocess failure rather than naming the
offending include. And the containment check has a TOCTOU window: it
canonicalizes `full_path` but the following `compat.readFileByPath` re-resolves
the original uncanonicalized path, so a symlink swapped in between defeats it.
Closing that means opening the canonicalized path (or opening first, then
validating via the file descriptor).

### Correctness and safety (vetted, lower leverage than the planned set)

- **`catch unreachable` on input-sized allocations.** `src/codegen.zig:1340`
  (`interface_ids.append` inside the entry-point emitter, grows with the shader's
  global count), `src/spirv_to_glsl.zig:3590,4219,4453`,
  `src/spirv_to_wgsl.zig:6021,6292`, `src/spirv_to_msl.zig:5262`. In a safe build
  each is a panic that aborts the host; the C ABI already has a
  `ZIOSHADE_ERR_OOM` status these should reach. Most enclosing functions already
  return error unions. Effort S.
- **Unguarded u16 word-count arithmetic in codegen.** `src/codegen.zig:1345`
  (`3 + name_words + @intCast(interface_ids.items.len)`, overflows at roughly
  65500 globals), `:3027` (`OpTypeStruct`), `:4688` (`OpTypeFunction`). Also
  `usize` subtractions that can underflow at `:5554`, `:6590`, `:6605`, and a
  paired-operand loop at `:6594-6598` reading `operands[i + 1]` without checking
  `i + 1 < len`. SPIR-V word counts are physically capped at 16 bits, so the
  honest outcome for an oversized module is a clear error, not a panic. Effort M.
- **`src/wasm.zig:206` returns uninitialized memory on format overflow.**
  `threadlocal var error_buf: [1024]u8 = undefined` (`:92`), and the fallback is
  `catch error_buf[0..error_buf.len]`, which hands JS up to 1 KiB of stale module
  memory when an error message exceeds the buffer. The C ABI's analogous path
  (`src/c_abi.zig:131-136`) correctly falls back to the error name; wasm is the
  outlier. One-line fix. Effort S.
- **`getCachedParse` is dead code with two latent hazards.**
  `src/spirv_cross_common.zig:1587-1604` keys a cached `ParsedModule` on
  `(ptr, len)` alone, so a freed-and-reallocated buffer at the same address
  returns a module describing the old contents while aliasing the new bytes (a
  silent miscompile), and it stashes the caller's allocator in a threadlocal for
  later eviction, which is a use-after-free if that allocator was a per-call
  arena. Zero call sites. Delete it. Effort S.
- **`src/cli.zig` silently swallows unknown flags.** The argument loop's final
  `else` at `:173-175` assigns any unrecognised token to `input_path`, so a
  mistyped `--shader-modell 50` is ignored and SM6.0 output is emitted with no
  warning. Separately, `:82,85,88,90,167` return from `main` on allocation
  failure with **exit status 0**, so `tools/*.sh` sweeps that read exit codes see
  success. 844 lines, 7 of the last 100 commits, zero tests. Effort S.

### Architecture and tech debt

- **45 ambient threadlocal globals across the four backends, with inconsistent
  reset discipline.** MSL 20, HLSL 12, GLSL 9, WGSL 4; `grep -c "defer g_"` gives
  msl 8, hlsl 4, glsl 3, wgsl 0. Concretely `src/spirv_to_glsl.zig:3558-3562`
  assigns `g_loop_phis = &loop_phis` (plus four siblings) to locals declared
  inside `emitBody`, with no `defer` reset in that function, so after it returns
  five threadlocals point at dead memory on that thread. Readers at `:994`,
  `:3785`, `:4005`, `:4082` cannot tell whether they are live. The cheap
  mitigation is a `defer g_x = null` at every assignment site (S); the real fix
  is an explicit `EmitCtx` threaded through the emit path (L, per backend).
- **Three of four backends keep private copies of shared functions.** WGSL
  correctly delegates to `spirv_cross_common.zig`; GLSL, HLSL, and MSL each carry
  a private `collectNames` (190, 150, and 161 lines respectively), a private
  `collectDecorations`, and a private `getDef`. The copies have measurably
  drifted: `grep -ci shadow` gives glsl 35, msl 20, wgsl 19, hlsl 6. The paired
  commits in `git log` (`b2ac34a` then `ab5621e`; `0b8d58c` then `35456d9`) show
  every name-mangling fix being authored two to four times, with a window where
  some backends have it and others do not. Do `getDef` and `collectDecorations`
  first (mechanical, output-identical), then `collectNames` parameterised by a
  per-backend reserved-word policy. Effort M to L.
- **`src/compact_ids_passes.zig` is 12719 lines holding 48 independent passes
  with zero inline tests.** Its own header says "only needed by codegen.zig" but
  it now has three importers (`src/codegen.zig:11`, `src/kernel_fusion.zig:7`,
  `src/loop_counter_phi.zig:8`). The passes are independent pure functions, so
  splitting into topic modules re-exported from a thin `passes.zig` is mechanical
  and requires no caller changes. This is the prerequisite that makes per-pass
  testing tractable. Effort L, but low risk (pure moves, verified byte-identical
  by the fixture gate). **`src/semantic.zig` (12247 lines) is explicitly not
  recommended for splitting**: shared symbol-table state makes it genuinely
  risky, and it needs characterization tests first.
- **Six optimizer passes have no test that names them at all.**
  `hoistInvariantACs`, `elimUninitVars`, `fixTypeOrdering`, `elimDeadFunctions`,
  `moveVarToEntry`, `stripDeadDebugInfo`. An optimizer bug emits *valid* SPIR-V,
  so spirv-val, the CTS sweep, and the validity sweeps all pass it; only the
  render-differential and metamorphic gates catch it, and both are local-only.
  Commit `cf8ed5f` ("metamorphic oracle (found/fixed an optimizer bug)") confirms
  this layer produces real silent-wrongs. A table-driven per-pass harness is the
  tractable shape. Effort L.
- **`src/opt_matvec.zig` is 413 lines of complete, unwired optimizer code.**
  `optimizeMatVecMul` has zero references across `src/`, `tools/`, `build.zig`,
  and the justfile; the only mention is `docs/ARCHITECTURE.md:50` saying it is
  unwired. Given the optimizer already re-copies the module 69 times, the
  recommendation is delete rather than wire up. Effort S.

### Performance

- **Roughly 95% of compile latency is unattributed.**
  `docs/IMPLEMENTATION_STATUS.md:250-257` puts cross-compile at about 40 µs and
  the full pipeline at 817 to 1292 µs, so nearly all of it is in GLSL to SPIR-V,
  the half with no internal instrumentation. Every harness
  (`tools/bench_perf.zig`, `bench_quick.zig`, `bench_compare.zig`) times only the
  public API boundary. `compileToSPIRVNoOpt` already exists at `src/root.zig:531`
  and would give the optimizer's share as a free A/B, but no benchmark uses it.
  This is the prerequisite for any optimization work. Effort S.
- **The optimizer runs 69 pass invocations, each re-parsing and re-copying the
  whole module.** `src/codegen.zig:239-418` is a straight-line chain where
  `deadCodeElim` alone appears 11 times and `compactIds` 5 times; every pass in
  `src/compact_ids_passes.zig` re-walks the word stream from index 5 and
  allocates a fresh full copy, with 212 `DynamicBitSet.initEmpty`/`AutoHashMap`
  constructions across the file. All of it runs on the caller's allocator
  (`src/root.zig:315-418`); the only arenas in the codebase are inside two
  backends. Two separately-shippable halves: wrap `codegen.generate` in an arena
  (mechanical, deletes about 69 lines of free-ceremony, byte-verifiable against
  the conformance corpus), then give passes a shared `PassContext`. **Measure
  first** via the attribution work above. Effort L, risk MED (pipeline ordering
  is empirically tuned, see the disabled-pass comment at `codegen.zig:361-363`).
- **Peak memory is a product metric that is instrumented nowhere.**
  `grep -rn "peak\|max_rss\|maxrss" tools/bench*.zig justfile` returns zero hits;
  all four published tables are latency and output size. For an in-process
  compiler in a GPU terminal this is a shipping constraint equal to latency, and
  there is no baseline against which a 10x regression would be visible. Effort S.

## Direction options (not problems, choices for the maintainer)

These are forward-looking product options, deliberately kept out of the ranked
findings. Each is grounded in something the repo already contains.

- **Finish the WASM playground.** `web/README.md:11-18` states the module
  compiles and exports the right symbols but "has not been run in a real
  browser", and `web/playground.js:5-7` repeats it. The build step is complete
  (`build.zig:1111-1150`), `src/wasm.zig` exposes all four backends, and the
  remaining work is enumerated in `web/README.md:52-70`: browser test, thread a
  stage argument through `zs_compile`, a Pages deploy, an optional `wasm-opt`
  trim. A paste-GLSL-see-four-backends page is the most persuasive artifact this
  project could have and the natural evaluation surface for anyone who cannot
  install a Zig toolchain. Effort S to M. The unverified `memory.grow`
  detachment path flagged at `web/README.md:56-58` is the main unknown.
- **Wire the front-end lib-vs-lib benchmark against `libglslang.a`.** Named as an
  open roadmap item in three separate documents (`README.md:165`,
  `BENCHMARKS.md:31` and `:49`, `docs/IMPLEMENTATION_STATUS.md:230`). The hard
  part is already solved: `tools/lib_bench.zig` plus `build.zig:826-869` links
  SPIRV-Cross's C API in-process from the Vulkan SDK, and glslang ships
  `glslang_c_interface.h` in the same SDK. This is the number that decides
  whether zioshade is "a faster integration story" or "a faster compiler", and it
  measures exactly the phase the 69-pass optimizer lives in. Worth naming the
  risk: the result may show zioshade is slower than in-process glslang, which
  would mean rewriting the performance framing again. The repo's track record of
  publishing the unflattering `lib-bench` number suggests that cost is accepted.
  Effort M.
- **Publish the conformance evidence as a live dashboard.** The generators
  already exist (`just status`, `just coverage-matrix`, `tools/prove_all.sh`,
  and roughly 75 files under `tools/` including tint, naga, Metal, DXC, and
  validity sweeps), and none of it is published or automated. The README frames
  the verification loop as this project's answer to "why trust a
  single-maintainer compiler", and that argument currently has to be taken on
  faith from prose. None of spirv-cross, naga, or Tint publishes anything
  comparable. Scope it to the sweeps that run unattended on hosted runners and
  mark the hardware-gated ones as maintainer-refreshed with a visible timestamp.
  A stale or red public dashboard is worse than none. Effort M.
- **Close G2, arbitrary SPIR-V consumption.** `docs/IMPLEMENTATION_STATUS.md:273`
  lists this as Tier 1 Critical: the backends assume zioshade-generated SPIR-V
  structure. `src/cfg_structurize.zig:189` already has `recoverLoopMerges` and
  `spliceLoopMerges`, unit-tested, with **zero callers**; the docs say composing
  them with selection recovery is future work. This is the half of the value
  proposition that does not require trusting the GLSL frontend at all, and it is
  what every prospective adopter who already has SPIR-V (from DXC, from glslang
  with `-O`, from a shader cache) runs into. Honest scope limit: valid Shader
  SPIR-V is always structured, so this affects externally-optimized and
  hand-authored modules rather than conformant ones, making the win adoption
  breadth rather than correctness. Start with a spike that measures the current
  failure rate and failure *shapes* against a corpus of externally-produced
  SPIR-V, before committing to the hard CFG work. Effort L, risk MED (it touches
  the pre-pass all four backends run). Irreducible CFGs must keep failing loud;
  that refusal is the contract, not something to soften.

## Findings considered and rejected

- **Untracked junk at the repository root** (`temp_0000.spv` through
  `temp_0024.spv`, `comp.spv`, `frag.spv`, `vert.spv`, `zig-out/`, `zig-pkg/`):
  not a finding. `.gitignore` covers all of it via root-anchored rules,
  `git status --short` is clean, and `git ls-files` shows no tracked `.spv`
  outside `tests/` and `src/testdata/`. Local working-tree clutter only.
- **`reflection.zig:358-364` `pos + wc` u32 arithmetic**: can only overflow on a
  module larger than 4 billion words, which is not reachable at realistic memory
  sizes.
- **The `zioshade_free_*` length-prefix layout being undefined behavior on a
  foreign pointer**: explicitly documented as UB at `include/zioshade.h:370-387`
  and a legitimate C library convention.
- **`ziotime` and `ziojson` as dependencies**: both are URL and hash pinned, so
  Zig's hash verification already blocks substitution. Inlining their four call
  sites would trade consumer simplicity for maintaining the Zig 0.15.2 to 0.16
  shim in two places, which is the reason those libraries exist. Judgment call,
  not a defect. Residual same-author-tarball availability risk is real but low
  leverage.
- **`continue-on-error` masking CI failures**: verified absent from `ci.yml` and
  the sweep scripts. Clean.
- **The Windows conformance cache workaround** (`ci.yml:111-117`): well reasoned,
  correctly scoped, with the failure mode written down.
- **`docs/internal` private submodule clone friction**: documented and worked
  around in `CONTRIBUTING.md`.
- **Splitting `src/semantic.zig`**: considered and explicitly not recommended.
  Shared symbol-table state makes it genuinely risky and it would need
  characterization tests first. The size is real; the fix is not worth it yet.
- **Generic "add more tests" and "add fuzzing" findings**: rejected as noise.
  This repo already runs a 2108-fixture spirv-val gate, a GPU render
  differential, CTS and GraphicsFuzz corpora, and structured fuzzing. The useful
  findings are about what that infrastructure does *not* cover, which is what the
  backlog above records.

### Prior-audit history: what was already known

A prior readiness sweep exists. On 2026-07-07 the founder asked for a
"pre-go public assessment", and a four-agent audit ran (fresh-clone stranger,
robustness and security probe, CI and hygiene, red-team). Its verdict was
"closer to launch-ready than most 10-week projects, but not safe to make public
today". Most of it shipped in PRs #422-427: a stack-buffer overflow in
`encodeStringLiteral`, SPIR-V stream-framing guards, parser recursion and
expression-depth limits, a macro-expansion budget, an aggregate-size cap, a
leaked API key purged from history, AI-attribution footers removed, CI made
green, and the dishonest benchmark headline rewritten. That work is real and it
is why the current audit found no findings in those areas.

Checking each of the six current findings against that history:

| # | Prior status |
|---|---|
| 001 conformance gate honesty | Never raised. The runner's `exit 0` was cited as *evidence of health* ("the suite exits 0"). |
| 002 truncated SPIR-V | **Partially covered.** PR #422 added *stream-framing* checks (`word_count == 0`, `i + word_count > words.len`, `bound > words.len`) and verified them against garbage and bit-flipped input. Correctly framed but operand-short instructions are a layer below that, and were never considered. |
| 003 C ABI cross-thread free | **Raised 2026-07-07 as HIGH, never fixed.** See below. |
| 004 include containment | Never raised in any session. |
| 005 optimizer alloc discipline | Never raised. |
| 006 `.paths` missing `include` | Same bug class fixed for `build_compat.zig` in PR #492, then certified closed on reasoning that only covered Zig imports. |

**Finding 003 is the one to look at twice.** The 2026-07-07 probe reached the
same diagnosis this audit did, independently and 27 days earlier:
*"HIGH: cross-thread free corrupts the heap. Allocator is `threadlocal`
(c_abi.zig:52); `zioshade_free_*` routes through the calling thread's GPA."*
It was carried in the workflow context alongside the C1-C5 items, but it is
absent from the PR #422 fix set and from the wave-completion report. It then got
harder to see rather than easier: `include/zioshade.h:27-31` now asserts
"Concurrent calls from different threads are safe" with no mention of the
constraint, and a 2026-07-31 accuracy review of threadlocal state did not flag
it. Known, dropped, then documented away.

**Why the robustness work does not cover 002.** The relevant fuzzers are scoped
to valid input by construction. `tools/spv_backend_fuzz.zig:4` states its own
scope: *"Fuzz-test all SPIR-V backends with random **valid** SPIR-V modules"*,
and every instruction it emits carries a hardcoded correct word count. The
100k-iteration structured fuzzer (`tools/fuzz_test.zig`) fuzzes **GLSL source**,
not SPIR-V. The e54.4 "robust arbitrary SPIR-V consumption" sweep feeds real
producer output (`tools/spv_input_validity_sweep.sh:7`: "output of glslang / DXC
/ spirv-opt"). Both `src/testdata/hostile_*.spv` fixtures were checked and
contain no short instruction. The prior work asked "does a *valid* module I did
not generate break my backends?"; nobody asked "does a *malformed* one crash
me?".

Worth noting because it is a documented claim this audit contradicts:
`docs/IMPLEMENTATION_STATUS.md:337` states that malformed input "still **fail[s]
loud** (`error.UnstructuredControlFlow`) - never miscompiled". That holds for the
CFG-structure class it describes. It does not hold for truncated instructions,
which abort with SIGABRT.

### Finding 002 is confirmed by reproduction, not by code reading

Against the CLI built from `0816eba`, truncating a single instruction inside real
GraphicsFuzz fixtures crashes **11 of 12** backend/fixture combinations with
SIGABRT (exit 134, "index out of bounds"). The reproduction recipe and the exact
output are inlined in `plans/002-spirv-min-word-count.md`. The remaining plans
are code-read findings verified at their cited lines; 002 is a demonstrated
crash.
- **Not audited in depth**: the GLSL frontend's language-semantics correctness
  (lexer, parser, semantic analysis against the GLSL specification), which would
  require specification-level review rather than code reading; the SPIR-V
  emission correctness of individual opcodes, which the existing differential
  and conformance infrastructure covers far better than a read-through could;

  The findings here concern the surfaces *around* that verified core: input
  validation, memory contracts, error handling, packaging, and what CI actually
